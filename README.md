# Steindamm 99 — Telegram Bot v2 (MVP)
Отдельный бот; старый репозиторий не затрагивается.

## Windows: запуск
1. Установите Python 3.11 или 3.12.
2. Скачайте репозиторий: Code → Download ZIP, распакуйте.
3. Откройте PowerShell в папке проекта.
4. Выполните: `py -m pip install -r requirements.txt`
5. Скопируйте `.env.example` в `.env` и укажите новый `BOT_TOKEN`.
6. Запустите: `py bot.py`
7. Во втором терминале: `py -m uvicorn api:app --host 127.0.0.1 --port 8000`
8. Откройте `http://127.0.0.1:8000` для локального просмотра Mini App.

## Telegram Mini App
Для запуска Mini App внутри Telegram нужен публичный HTTPS-адрес, например через временный туннель. Укажите его в `WEBAPP_URL`, затем перезапустите бота. Локальный предпросмотр `LOCAL_PREVIEW=1` не предназначен для публичного доступа: перед открытием туннеля установите `LOCAL_PREVIEW=0`.

## Статус
Работает: /start, запрос собственного контакта, SQLite, Mini App, локальный тест формы отзывов, серверная проверка Telegram initData.
Демо бронирования: кнопка «Забронировать столик» открывает действующую страницу Restoplace во встроенном iframe; если провайдер блокирует встраивание, есть прямая ссылка. Свободные слоты и создание брони обслуживает Restoplace, отдельного API пока нет. Проверить на смартфоне и в Telegram: сайт Restoplace может запретить iframe через X-Frame-Options/CSP.
Не готово: собственная интеграция с API Restoplace, уведомления администратору, юридические документы, продакшн-развёртывание. Бронирование намеренно отключено, пока не подтверждены API-методы и права доступа. Для реального использования нужно проверить требования к хранению персональных данных.
Не публикуйте токен Telegram и API-ключи в GitHub. `.env` игнорируется Git.

## База гостей и статус постоянного гостя
В SQLite автоматически хранятся Telegram ID, имя, телефон, отзывы и история подтверждённых бронирований. Данные сохраняются при обновлении через Git и перезапуске приложения, если файл `steindamm.db` остаётся на месте.

**Важно:** текущий встроенный виджет Restoplace не передаёт нашему приложению факт бронирования и Telegram ID гостя. Поэтому **автоматический подсчёт бронирований пока не работает**. Для тестирования и ручного занесения реально подтверждённых броней есть закрытые команды администратора; после согласования API или надёжного механизма синхронизации подключим автоматический импорт. Одну бронь нельзя засчитать дважды по одинаковому внешнему ID. Отменённые брони не учитываются. Статус «Постоянный гость» определяется при **5 и более подтверждённых, не отменённых бронях**, это не счётчик фактических визитов.

### Настройка администратора
В приватном `.env` установите `ADMIN_CHAT_ID=123456789`, где число — ваш личный Telegram user ID (он же ID личного чата с ботом). **Не указывайте ID группы.** Перезапустите `py bot.py`. Команды с личными данными доступны только этому пользователю в личном чате. Токен и файл `.env` не публикуйте.

Команды: `/admin` (справка), `/guests` (статистика), `/regular` (постоянные гости), `/guest 123456789` (карточка), `/reviews` (10 последних отзывов), `/exportguests` и `/exportregular` (CSV с BOM и разделителем ;, удобно открывать в Excel), `/addbooking 123456789 RESTO-1001` (вручную добавить **реально подтверждённую** бронь), `/cancelbooking RESTO-1001` (исключить отменённую бронь). Для поиска ID гостя используйте выгрузку. До интеграции с Restoplace проверка броней осуществляется человеком.

**Внимание к персональным данным:** CSV содержит телефоны гостей. Храните его защищённо, не пересылайте посторонним. До публичного запуска подготовьте политику конфиденциальности, основания обработки и соблюдение применимых требований к размещению/хранению персональных данных, в том числе российских. SQLite-файл нуждается в резервном копировании. Для публичного серверного размещения потребуются контроль доступа, защита хоста и порядок удаления данных.
