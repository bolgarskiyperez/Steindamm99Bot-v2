# Steindamm99Bot-v2 — отдельная демонстрационная версия V3

Этот проект подключается **только к отдельному тестовому заведению Restoplace**. Он не готов к работе с настоящими персональными данными гостей на зарубежном Render. Политика и согласие в приложении являются проектами и требуют утверждения оператором.

## Настройка Render (Environment)

```env
BOT_TOKEN=...
WEBAPP_URL=https://steindamm99bot-v2.onrender.com
RUN_BOT_IN_API=1
ADMIN_IDS=<telegram-id-уполномоченного-администратора>
RESTOPLACE_MODE=test
RESTOPLACE_TEST_API_KEY=<API-ключ-ТОЛЬКО-отдельного-тестового-заведения>
RESTOPLACE_TEST_VENUE_CONFIRMED=yes
RESTOPLACE_TEST_WRITES=true
RESTOPLACE_WEBHOOK_SECRET=<случайная-строка-минимум-32-символа>
ALLOW_CONTACT_GROUP_NOTIFICATIONS=0
FEEDBACK_AUTO_DEMO_ENABLED=1
REAL_CONTACT_TEST_ENABLED=0
ALLOW_LEGACY_EXPORT=0
```

Никогда не сохраняйте токены и ключи в репозитории, переписке, клиентском JavaScript или скриншотах. Ключ **боевого** заведения нельзя указывать как `RESTOPLACE_TEST_API_KEY`.

### Режимы

- `RESTOPLACE_MODE=mock` — обращения к Restoplace отключены, запись невозможна (режим по умолчанию).
- `RESTOPLACE_MODE=test`, `RESTOPLACE_TEST_WRITES=false` — только чтение доступных слотов тестового заведения.
- `RESTOPLACE_MODE=test`, `RESTOPLACE_TEST_VENUE_CONFIRMED=yes`, `RESTOPLACE_TEST_WRITES=true` — разрешены **записи только в тестовый аккаунт**, ключ которого предоставлен. Создание тестовых броней доступно любому пользователю, который открыл Mini App через Telegram с корректным подписанным `initData`.

По умолчанию в Restoplace отправляются синтетические контактные данные `Тестовый гость Steindamm99` / `79990000000`. При `REAL_CONTACT_TEST_ENABLED=1` любой пользователь с подтверждённым Telegram `initData` сможет оформлять бронь на своё имя и телефон, который он сам передал боту. Список Telegram ID не используется. Перед такой записью пользователь должен отправить свой номер через кнопку Telegram-бота. Не включайте это для других гостей и не публикуйте настоящие данные на иностранном Render без отдельного правового решения. Депозиты при создании тестовых броней выключены. Проверяйте настройку тестового заведения до включения записи.

## Включение Mini App

После успешного автодеплоя Render отправьте боту команду `/start` и откройте приложение через кнопку **Меню** Telegram. Она использует подписанный `initData`; запуск старой кнопкой клавиатуры без подписи не поддерживается.

Адрес интерфейса: `/app-demo-v3-20261103`.

## Webhook

В тестовом Restoplace включите события **reserve.created** и **reserve.updated**, URL:

`https://steindamm99bot-v2.onrender.com/api/restoplace/webhook/<RESTOPLACE_WEBHOOK_SECRET>`

Секрет — ваш уникальный, длиной не менее 32 случайных символов. URL рассматривается как секрет: не публикуйте его. В документации Restoplace не подтверждена подпись событий; проверка секретного пути обеспечивает только базовую защиту тестового стенда, **не является проверкой криптографической подписи Restoplace**. Обработчик игнорирует посторонние бронирования, не сохраняет имена и телефоны из webhook, изменяет статусы только у записей, созданных ботом и известных локальной базе.

## Что уже есть в демонстрации

- Чтение доступности 1–4 гостей из `GET /times/` с шагом 30 минут и длительностью 120 минут.
- Создание брони 1–4 гостя через `POST /reserves/`.
- Создание заявки в лист ожидания для 5–20 гостей с `waitlist=true`.
- Экран «Мои брони», тестовая история, отзывы, кабинет ресторана, поиск гостей по тестовым бронированиям, статусы и CSV-выгрузка тестовой базы.
- Уникальный ключ запроса, защита от повторных нажатий, блокировка автоматических повторов после неопределённого результата.
- Чтение статусов через webhook для известных тестовых резервов. Сотрудники могут отметить приход или отменить тестовую бронь. При `FEEDBACK_AUTO_DEMO_ENABLED=1` после закрытия посещённого резерва webhook может один раз отправить тестовое сообщение с просьбой оставить отзыв.
- Старый интерфейс остаётся доступным через прежние маршруты как резервный.

## Ограничения перед демонстрацией

1. **Нет API-ключей в репозитории**, поэтому создание реальных тестовых броней необходимо проверить после настройки Render. До этого сквозная проверка Restoplace невозможна.
2. У Render Free временная файловая система. Локальная SQLite, в том числе история тестовых операций и дедупликация, может сброситься после деплоя/перезапуска. Не нажимайте «Создать» повторно после тайм-аута, пока не сверите запись в Restoplace.
3. Это **не production-реализация 152-ФЗ**. Используйте только искусственные контактные данные и тестировщиков; никогда не подключайте ключ реального ресторана к Render.
4. База постоянных гостей пока рассчитывается не по полной истории Restoplace. Переход на PostgreSQL, полноценная синхронизация внешних броней, подтверждённые визиты, согласия, удаление данных и резервные копии — отдельный этап production.
5. Формат запроса создания `POST /reserves/` должен быть подтверждён первым безопасным тестом на отдельном заведении. Отсутствие описанной серверной идемпотентности Restoplace не позволяет гарантировать отсутствие дубликатов после неизвестного исхода.
6. Для production webhook потребуется дополнительная проверка доверенности отправителя и обработка событий, поступающих не по порядку.

## Сценарий проверки

1. Откройте тестовый кабинет Restoplace, проверьте, что он не связан с рабочим рестораном.
2. Включите режим только чтения и проверьте свободные слоты в Mini App.
3. Разрешите запись и создайте **одну** тестовую бронь на 2 гостей.
4. Сверьте присвоенный ID и номер бронирования в Restoplace.
5. Создайте **одну** заявку в лист ожидания на 5 гостей.
6. Измените статус в тестовом Restoplace либо отметьте приход из панели бота; проверьте обновление статуса в Mini App.
7. Проверьте доступ к админ-панели и отсутствие доступа у обычного гостя.


## Изменения интерфейса и сообщений (03.11.2026)

- Поле выбора даты исправлено для узких экранов iPhone/Android, количество гостей — 1–20 (от 5 — лист ожидания).
- Оценка отзыва — 1, 2, 3, 4 или 5 звёзд.
- В CRM: поиск по имени, телефону и Telegram ID; фильтр даты регистрации, сортировка по имени, посещениям, бронированиям и дате, отдельно помеченные вымышленные примеры.
- Команда `/testfeedback` в личном чате Telegram мгновенно показывает шаблон запроса обратной связи с кнопкой Mini App, без ожидания и без создания брони.
- `FEEDBACK_AUTO_DEMO_ENABLED=1`: сервер проверяет брони раз в минуту **пока работает** и отправляет сообщение примерно через 30 минут после двухчасового бронирования, **только если тестовый гость отмечен как пришедший или завершивший визит**. Не отправляет для листа ожидания или отменённого визита. База хранит отметку об отправке. На бесплатном Render, который засыпает и теряет SQLite на деплое, гарантировать точность отправки нельзя.
- Для реальных имён и телефонов используется отдельный флаг `REAL_CONTACT_TEST_ENABLED=1`; авторизация через Telegram и передача собственного контакта обязательны. Не включайте режим для публичного тестирования без юридической проверки. Российскую production-инфраструктуру это не заменяет.
